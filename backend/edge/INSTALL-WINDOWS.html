Servidor local no PC da loja — passo a passo

Cada passo tem Ação, Onde, Como e Confirmação. Marque ✓ ao concluir. Se a confirmação não bater, pare e resolva antes de seguir.

0 de 13 passos concluídos
🌐 Internet só no setup: a instalação precisa de internet para baixar as dependências e ativar a licença na nuvem. Depois de instalado, o servidor roda offline — a loja opera sem internet e sincroniza quando reconecta.
⚠️ Antes de começar, tenha em mãos 2 informações da nuvem: o token do equipamento servidor_local (passo 6) e a chave pública da licença LICENSE_PUBLIC_KEY_B64 (passo 6). Sem elas, sync e licença não funcionam.

Parte A — na sua máquina (gerar o pacote)

1.Compilar e empacotar

Onde: terminal na pasta backend do projeto.
Como:
npm ci
npm run build
node edge/package.mjs
Confirmação: aparece Pronto: ...\regem-edge-dist e a pasta regem-edge-dist existe.

2.Levar para o PC de teste

Como: copie o conteúdo de regem-edge-dist para C:\regem-edge\backend no PC de teste (pen drive/rede).
Confirmação: no PC de teste existe C:\regem-edge\backend\dist\main.js e a pasta ...\backend\edge.

Parte B — no PC de teste (a máquina da loja)

3.Pré-requisitos

Como: instale, nesta ordem:
1. Node.js 20+ LTS — nodejs.org
2. PostgreSQL 15+ — postgresql.org · anote a senha do postgres, porta 5432
3. NSSM — nssm.cc · ponha nssm.exe numa pasta do PATH
4. OpenSSL — vem com o Git for Windows
Confirmação: no PowerShell, node -v, nssm version e openssl version respondem sem erro.

4.Dependências + banco local

Onde: PowerShell em C:\regem-edge\backend.
Como: (troque SUA_SENHA)
cd C:\regem-edge\backend
npm ci --omit=dev
node -e "const{Client}=require('pg');(async()=>{const c=new Client({connectionString:'postgresql://postgres:SUA_SENHA@localhost:5432/postgres'});await c.connect();await c.query('create database regem_local').catch(()=>{});await c.end()})()"
Confirmação: npm ci termina com added N packages; o comando do banco volta ao prompt sem erro.

5.Configuração (.env.local)

Como:
Copy-Item edge\.env.local.example .env.local
notepad .env.local
Preencha: DATABASE_URL/EDGE_DATABASE_URL (senha), JWT_SECRET (16+ chars), EDGE_UNIDADE_ID. Deixe SYNC_TOKEN e LICENSE_PUBLIC_KEY_B64 para o passo 6.
Confirmação: o arquivo existe e o DATABASE_URL aponta para localhost:5432/regem_local — não a nuvem!

6.Token + chave pública (na nuvem)

Onde: app.dmsregem.com, como presidente/gerente.
Como: Cadastros → Equipamentos → Novo, tipo servidor_local → copie o token (aparece 1 vez) para SYNC_TOKEN. Peça a quem gerou as chaves o LICENSE_PUBLIC_KEY_B64 e cole no .env.local.
Confirmação: SYNC_TOKEN=... e LICENSE_PUBLIC_KEY_B64=... preenchidos.

7.Migrations no banco local

Como:
node scripts\apply-all-local.mjs
Confirmação: lista de migrations aplicadas, sem linha em vermelho.

8.Certificado HTTPS local

Como: rode ipconfig, anote o IPv4 (ex. 192.168.1.2) e gere o certificado:
node edge\gen-cert.mjs 192.168.1.2
Confirmação: existe edge\certs\ com ca.pem, server.crt, server.key.
Reserve esse IP no roteador (DHCP por MAC) para ele não mudar ao reiniciar.

9.Subir como serviços do Windows

Onde: PowerShell como Administrador.
Como:
cd C:\regem-edge\backend
.\edge\instalar-servicos.ps1 -Raiz "C:\regem-edge\backend"
Confirmação: Serviços RegemEdgeApi + RegemEdgeSync ativos; no services.msc os dois estão Em execução / Automático.

10.Testar o servidor

Como: no navegador do PC, abra:
https://localhost:3001/api/v1/ping
Confirmação: volta {"regem":true,"edge":true,...} (o aviso de certificado em localhost é normal).

11.Ativar a licença

Onde: na nuvem, tela /frota.
Como: Emitir token para a loja (tenantId, ramo food service, plano, módulos) → copie o token. No PC de teste:
curl.exe -X POST https://localhost:3001/api/v1/provisionamento/ativar -H "content-type: application/json" -d "{\"token\":\"COLE_O_TOKEN\",\"fingerprint\":\"pc-loja-01\"}"
Confirmação: resposta com lease; minutos depois a loja aparece 🟢 online em /frota.

12.Confiar o certificado nos clientes

Onde: em cada aparelho cliente (KDS/PDV/Ponto).
Como: copie edge\certs\ca.pem para o aparelho → abra certlm.msc → Autoridades de Certificação Raiz Confiáveis → Certificados → Importar → selecione o ca.pem.
Confirmação: "Regem Edge CA" aparece nas raízes confiáveis.

13.Apontar os clientes para o servidor

Onde: navegador de cada aparelho, na mesma rede.
Como: abra https://regem.local:3001 (se resolver mDNS) ou https://192.168.1.2:3001 (o IP do passo 8).
Confirmação: abre com cadeado (sem aviso) e /api/v1/ping retorna o JSON. Câmera do Ponto e modo offline funcionam.

Depois — testar a atualização automática (Fase E-D)

1) Na sua máquina:
.\edge\publicar.ps1 -Versao 1.4.0
Suba o .zip num HTTPS e cole as 3 variáveis (EDGE_LATEST_VERSION / EDGE_UPDATE_URL / EDGE_UPDATE_SHA256) no regem-api.
2) No PC de teste (Admin, loja fechada):
.\edge\atualizar.ps1 -Raiz "C:\regem-edge\backend"
Confirmação: confere o SHA-256, faz backup, troca, migra, health-check no /ping e faz rollback se falhar.
